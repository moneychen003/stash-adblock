# 旧广告、缓存与重新安装

**更新：2026-11-04**

有些 App 可能保留已经下载的开屏素材或本地状态。规则已经更新后仍看到旧广告，**不等于所有广告都来自缓存**；广告接口漏拦、规则冲突、频控、新用户策略或登录状态也可能影响结果。按下面的顺序排查，重装只放在最后。本公开覆写适用于 Stash 3.6+，无需替换原有节点配置。

## 从轻到重

1. **确认规则有效。**检查 Stash 正在连接、覆写已启用、改写/脚本及需要的 MitM 正常；确认导入的是本项目的覆写地址，而非节点配置。更新远程覆写并应用。
2. **冷启动复测。**完全退出目标 App，再打开。约第 2、5、8 秒观察，10 秒内没有有效结果就记「跳过/未取得结果」。不要把 App 自带品牌页或广告倒计时结束后的首页当成广告被拦截。
3. **仅清目标 App 能安全识别的缓存。**如果 App 有官方缓存清理入口，先看清它会删除什么，备份或同步需要保留的内容，再清理；不要笼统清除全部数据。清完按相同方法复测。
4. **仍有问题时，才考虑彻底删除并从官方商店重装。**先核对账号能重新登录、内容已同步或备份、需要保留的本地下载及设置已经记录。iOS 的「删除 App」会移除 App 及其本地数据；「卸载 App」可能保留文稿与数据，两者不能当作相同的干净重装。重装可能需要 App Store 认证，首次打开也可能要求同意协议。请自行决定是否接受这些影响。

本地下载、未同步歌单、历史设置和其他仅保存在设备上的内容可能丢失。重装前后尽量保持**同一 App 版本、同一规则与相近测试条件**，才能更清楚地比较；若版本变了，要注明。重装后仍有广告也应如实记录，不能继续反复删除碰碰运气。

## 已观察到什么

**以下QQ音乐和优酷结果属于历史组合。当前版本与本轮观察以[效果表](APP-STATUS.md)为准；优酷本轮已是11.2.21，首页推广仍有，不能沿用旧版重装后的成功作为全部广告位通过。**

QQ 音乐 20.9.6 曾在系统离线设置下显示完整商业开屏。随后从官方商店删除并重装同版，在四次有图启动观察中未再见该开屏，其中两次已经撤回临时诊断、使用原正式规则，首页正常。这**支持**旧本地状态可能参与，但没有找到具体缓存文件，也不能排除新安装用户策略或频控；登录后和长期效果未验证。

优酷此前在系统离线设置下仍有完整开屏。用户于 **2026-11-04 明确反馈**：手动重装 11.2.19 后去广告成功。这是用户确认的结果，不是与 QQ 音乐相同的四次自动化代理实测；登录后与长期效果仍需在实际使用中观察。不要把这两个 App 的结果推广到所有 App，也不能据此认定旧缓存是唯一原因。
