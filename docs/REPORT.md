# 测试与发布记录

**规则版本：2026.11.04.3｜日期：2026-11-04**

## 转换与范围

从固定 fmz 原文出发，对全部 4383 条启用语句生成处理记录。最终为 2480 条分流、1085 条 URL 改写、29 条正文改写、157 条脚本绑定、76 个 provider 和 977 个 HTTPS 主机条目。具体来源与排除理由见[覆盖说明](COVERAGE.md)。

## 本地已检查

- 构建可重现、输入版本和文件哈希固定，启用源语句逐行对账，无静默遗漏。
- 生成正则、脚本语法、原生 jq 表达式及异常响应透传。
- 实测补丁优先级、对应 HTTPS 主机、普通账户与授权接口不被混合脚本挂载。
- 拼多多只删除投放标记项；豆瓣／知乎／小红书的大整数原文保留。
- 京东编码开屏响应、广电业务导航、优酷播放与水印、视频专用广告字段、YouTube JSON／protobuf 原始字段保留。
- 公开文件扫描：不含用户证书、控制密钥、私人地址、文件路径或设备应用库存；第三方独立脚本使用固定来源引用。

本地样例通过不是全部客户端实测通过。爱奇艺、芒果 TV、YouTube 等若没有实际设备观察，不能把样例结果写成广告已消失。

## 手机观察

设备已同步私人候选文件，保留自己的证书、家庭路由和 DNS，旧八条覆写作为停用备份。公开版不含这些私人字段；广告脚本预载内容与公开固定版本哈希核对一致。

本轮对13款App共做16轮限时观察；QQ音乐按使用者此前要求不继续复测，沿用历史。实际观察见[App 效果表](APP-STATUS.md)，机器可读摘要见 [device-verification.json](../rules/device-verification.json)。已观察到 Stash 配置诊断无警告，基于规则的 Apple 请求成功。一项原 DNS 诊断失败在升级前已出现，私人 DNS 没有改动；不能把它算成新广告规则成功或失败。

首轮豆瓣出现广告占位，已补回旧版的 API QUIC 回退后，后续连续两轮采样未见原占位并进入首页。微博首轮出现完整商业开屏，后续一轮未再见开屏但现金推广仍在，记录为表现波动。未完成的旧版对照不能作为“已经证明是缓存”的结论，后续若复测也应注明版本、登录态与是否清缓存。

本轮没有重装 App、执行新的缓存删除、登录、支付或修改账户权益。十秒内无有效结果、协议／认证／权限阻挡及界面干扰均不算去广告通过。原始图片、请求、设备与操作记录只留本机，不发布。

## 结果怎么使用

本项目提供去广告规则及可复核的适配记录，不提供全部 App／全部广告位永久无广告承诺。换设备、账号、地区、版本及客户端缓存都可能改变表现。旧版成功、使用者反馈、本轮画面观察、请求命中和离线样例是不同证据，不能相互替代。

问题反馈按[模板](TROUBLESHOOTING.md)提供可公开的版本、广告位置和观察结果，不上传完整抓包或私人配置。
