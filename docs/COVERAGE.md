# 覆盖范围与公开处理说明

**版本：2026.11.04.2。**主订阅已经由首版的小范围版本改为保留原工作组合中的广告功能。不是按 App 类型挑选七八个应用：只要是原有广告处理，就保留；没有把金融、购物、工具或小程序整体排除。

## 已恢复

- 通用域名／SDK 广告拦截与 AWA 规则集引用。
- 原有 App、小程序的广告 URL 改写和上游广告脚本引用。
- 七个原有本地处理器：豆瓣广告开关、微博推荐直播、拼多多标记广告推荐、中国广电开屏及营销楼层、酷安启动响应、京东开屏、哔哩哔哩开屏。
- 雪球独立规则中的精确广告与推广接口，包括有命中证据的 `promotion/display_ad_batch.json`，合并进同一主订阅。
- QQ 音乐、优酷的广告域名及精确接口。优酷混合脚本改为本仓库去广告专用版本，保留播放流、水印、正常导航和青少年模式。

原配置中的三个微博 `DIRECT` 例外也保留。它们只针对需要进入本机 HTTP 改写的广告接口主机，用于避免先被通用域名规则直接拒绝；没有带入个人节点、代理组或全局直连偏好。

## 删除或调整的内容

| 内容 | 处理 |
| --- | --- |
| 私人内容 | 不发布设备清单、设备标识、账号、抓包、证书、控制密钥、局域网服务地址、个人文件路径或安装包。 |
| 个人网络偏好 | 不带入个人 DNS 配置、节点和控制端口。原有针对广告绕过的部分传输限制属于广告规则，不等同于个人 DNS 设置。 |
| 非广告功能 | 删除会员等级／到期时间改写，以及阻断许可激活、支付、认证、安全浏览、更新等规则。 |
| 过宽的整页拒绝 | 删除直接阻断正常账号、订单、服务页、通用图片资源或混合配置的规则；保留明确广告位。删除清单公开列出理由。 |
| 混合脚本 | 只挂载广告路径；无法拆分的非广告分支不启用。优酷改用广告专用处理器，不再把删水印、改普通页签混进广告处理。 |
| 无处理器的 MitM 主机 | 清理不用的主机；对保留接口检查主机覆盖，避免只恢复规则却忘记相应 HTTPS 主机。保留必要的有限域名通配。 |

具体计数、原规则索引、被删规则文本及理由见 [coverage.json](../rules/coverage.json)。本清单不含个人应用库存。

因此公开版仍不是私人配置的逐字节副本，但差异有逐项理由，不能再把来源整理当作大量删除广告覆盖的理由。可追溯到有许可上游的域名／改写保留来源与署名；第三方独立脚本仅作固定版本 URL 引用，详见[来源与许可](../THIRD_PARTY.md)。

## 验证边界

这次更新验证了构建一致性、保留接口的规则优先级、HTTPS 主机覆盖、依赖下载、脚本语法与定向样例。拼多多只过滤带广告标记的推荐并保留大整数原文；京东兼容已观察到的编码开屏响应；中国广电保留充值／账单导航；优酷样例保留播放字段、水印与普通页签。

这些是配置与样例验证。历史实机结果见[逐项效果](APP-STATUS.md)，不能写成这次公开生成文件已经在所有设备、账号和版本上重新跑完，也不能把短时没有出现广告推广为全 App 无广告。

## 已安装首版怎么办

主订阅地址不变。在 Stash 中更新这个远程覆写、重新应用，确认没有同时启用其他重复的广告覆写，再完全退出目标 App 复测。不要同时叠加首版副本、手机版大聚合副本和本完整版，避免多份规则与同名处理冲突。节点配置及自己的 CA 无需删除。
