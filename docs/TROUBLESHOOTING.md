# 故障排查与反馈

**更新：2026-11-04**

适用于 Stash 3.6+ 的公开覆写；安装时无需替换原有节点配置。公开版仅包含 AWA 通用广告域名拦截和少数 App 核心规则，历史私有配置中的其他模块不在此范围。

| 现象 | 先检查什么 |
| --- | --- |
| 一键链接打不开、提示 403 或 404 | 一键导入服务也可能拒绝请求；此时直接复制主订阅地址手动添加远程覆写。若原始文件也打不开，检查网络及地址、分支、文件名，核对 [主订阅地址](../README.md#一键安装)。不要把它作为节点订阅导入。 |
| 已导入但没有变化 | 确认 Stash 已连接、覆写已启用并更新应用；检查改写、脚本及目标 HTTPS 规则需要的 MitM/本机 CA 信任。其他覆写的顺序和规则也可能影响命中。 |
| 仍有旧开屏 | 完全退出 App 后按 2/5/8 秒观察；先看是否为品牌页或倒计时结束的首页。再依照[缓存与重装](CACHE-AND-REINSTALL.md)由轻到重排查。 |
| 有些广告消失，有些还在 | 请报具体 App、版本、页面和广告位。规则只覆盖已识别的请求；活动运营位、账号状态和 App 更新会改变结果。 |
| 页面空白或功能异常 | 暂时关闭本覆写并重开目标 App，对比是否恢复；若恢复，请记录 App 版本、页面、发生时间及可公开截图后反馈。不要直接清除全部 App 数据。 |
| 重装后第一次出现协议页 | 按自己的意愿处理协议，进入正常页面后再复测；单凭协议页不能判断去广告效果。 |

## 维护与反馈

请到 [GitHub Issues](https://github.com/moneychen003/stash-adblock/issues) 报告失效或功能异常。维护者会依据可复现信息检查规则，不能把尚未测试的 App 默认算作成功。

建议按下面的格式提交：

```text
App 名称与版本：
Stash 覆写更新时间：
问题页面/广告位置：
冷启动第 2、5、8 秒看到什么（10 秒无结果写「未取得结果」）：
是否为品牌页、商业广告，或倒计时后的首页：
是否登录、是否刚重装、是否清过缓存：
关闭本覆写后是否仍出现（如已安全对照）：
```

截图可以只截广告区域，并遮盖账号、通知等信息。**不要公开**完整个人 App 清单、设备型号与序列号/UDID、Wi-Fi 或内网/Tailnet 地址、账号资料、原始抓包日志、IPA、个人文件路径、控制密钥或 CA/私钥。远程脚本由各上游维护；发现脚本异常时，也请说明涉及的功能与版本，避免发送私人数据。
